# v2.0 Release Readiness Checklist

This checklist helps contributors prepare a **v2.0.0** release for OBS Duel Recorder.

Scope:
- Documentation and verification steps for **v2.0 - OCR Integration** readiness.
- v2.0 uses image recognition first; heavyweight OCR/ML runtime dependencies are non-goals unless separately approved.
- No implementation work is performed by this checklist.

Quick links:
- Version tracking issue: #324
- Acceptance checklist: `docs/requirements/v2.0-ocr-integration-acceptance.md`
- Image recognition architecture contract: `docs/architecture/image-recognition.md`

Non-goals:
- Completing v2.1 Statistics System.
- Making image recognition the primary duel trigger.
- Shipping game assets, user screenshots, or training data.

---

## A. Milestone Readiness

- [x] Required v2.0 child issues are closed or explicitly deferred with a clear note.
- [x] Any deferred issues have a target version or follow-up issue.
- [x] Version tracking issue #324 reflects final child issue state.
- [x] Open v2.0 PRs are merged or explicitly deferred.
- [x] Superseded duplicate v2.0 tracking issues are identified for cleanup.

## B. Documentation Readiness

- [x] Canonical docs are up to date:
  - [x] `docs/roadmap.md`
  - [x] `docs/requirements/requirements.md`
  - [x] `docs/traceability.md`
  - [x] `docs/requirements/v2.0-ocr-integration-acceptance.md`
  - [x] `docs/architecture/image-recognition.md`
  - [x] `docs/architecture/packaging.md`
  - [x] `docs/architecture/upload-provider.md`
  - [x] `docs/architecture/worker-api.md`
- [x] README current development and latest release sections are ready for the release handoff.
- [x] Release history update is prepared.

## C. Verification - Image Recognition

- [x] Image recognition provider boundary tests pass.
- [x] Fixture-backed result, rank, and DP recognition tests pass.
- [x] Fixture minimum success criteria are met and recorded.
- [x] Metadata correction/fallback behavior is tested.
- [x] Plugin UI/manual correction smoke notes are recorded.
- [x] No runtime videos, screenshots, DBs, logs, credentials, model files, game assets, or generated media are committed.

## D. Packaging / Release Asset Readiness

- [x] GitHub Actions ZIP generation is available or explicitly deferred with a follow-up.
- [x] Release ZIP layout matches `docs/architecture/packaging.md` or any deviation is documented.
- [x] SHA256 checksum generation is available or explicitly deferred with a follow-up.
- [x] Final release asset publication requires maintainer approval.
- [x] Upload provider work is either completed in scoped child issues or explicitly deferred; v2.0 image recognition release must not accidentally require Google upload dependencies.

## E. Release PR Readiness

- [x] Release PR contains no secrets and does not add runtime data, logs, databases, videos, screenshots, OAuth files, local templates, model files, or game assets.
- [x] Release PR updates persistent release docs.
- [x] Release PR is merged into `main`.
- [x] The merge commit SHA on `main` is recorded for tagging.

## F. Tagging After Merge

- [x] Create tag `v2.0.0` pointing to the release merge commit SHA on `main`.
- [x] Do not move or overwrite existing tags.
- [x] Tag target SHA is recorded in #324 and release docs.

## G. Handoff

- [x] Next version tracking issue #325 is linked from #324.
- [x] Deferred work is linked to follow-up issues or later version tracking.
