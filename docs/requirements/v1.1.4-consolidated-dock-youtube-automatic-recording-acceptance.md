# v1.1.4 Consolidated Dock, YouTube, And Automatic Recording Acceptance

Tracking issue: #473

Required issue range: #473 through #504

## Scope

`v1.1.4` consolidates the current Dock UI quality work, YouTube readiness
improvements, and guided automatic recording setup into one release target.

The release must preserve the repository responsibility boundary:

- OBS Plugin owns OBS integration, Dock UI, current-screen capture transport,
  and Worker lifecycle.
- Python Worker owns persistence, upload/OAuth, queue behavior, template
  storage, image matching, detection, and recovery-safe runtime behavior.
- Runtime files stay under `user_data/` and must not be committed or packaged.

## Dock UI Acceptance

- [ ] Dock uses the agreed Record / Upload / Manage tab structure.
- [ ] Dock uses coherent light-green color roles with red reserved for errors
      and destructive actions.
- [ ] Major controls have documented icons and tooltips.
- [ ] Record tab shows recording state and a switching start/stop control.
- [ ] Record tab supports direct metadata editing for deck, opponent deck,
      result, rank, DP, and memo.
- [ ] Deck and opponent deck inputs remain editable dropdowns.
- [ ] Deck, opponent deck, rank, and DP carry over from previous saved values
      when a new target has empty fields.
- [ ] Record tab shows the current metadata editing target video identity.
- [ ] Record tab reserves a stable target-video preview area.
- [ ] A valid metadata target video shows at least one thumbnail or a clearly
      documented representative-frame fallback.
- [ ] Target-video preview always represents the current metadata editing
      target, not an arbitrary queue item.
- [ ] Upload tab shows upload queue state, current actionable item, and queue
      actions.
- [ ] Template tab supports upload title, description, and tags template editing.
- [ ] Upload preview and real upload use the same Worker-rendered metadata
      contract.
- [ ] Upload tab shows YouTube/OAuth readiness without exposing secrets.
- [ ] Manage tab contains setup, settings, language selection, automatic
      recording setup, and diagnostics/details.
- [ ] Raw/debug-heavy details are hidden behind explicit details controls by
      default.

## YouTube / Upload Acceptance

- [ ] Worker exposes a stable upload readiness contract for Plugin/UI use.
- [ ] Upload readiness distinguishes provider availability, dependency
      availability, client secret presence, token presence, token state, refresh
      availability, quota waiting, manual review, and next action.
- [ ] OAuth setup and recovery are operator-guided and documented.
- [ ] OAuth client secret, token, authorization code, bearer strings, and token
      JSON contents are never exposed in UI, logs, diagnostics, exports, or
      support bundles.
- [ ] Quota errors are classified separately from network and auth failures.
- [ ] Manual review retry warns about duplicate upload risk.
- [ ] Mark-uploaded requires a YouTube video ID and stores deterministic
      YouTube URL state.
- [ ] Upload metadata preview shows title, description, tags, missing metadata
      warnings, and privacy status.
- [ ] Upload privacy defaults remain private, unlisted remains allowed, and
      public upload is not introduced without a separate explicit decision.

## Guided Automatic Recording Acceptance

- [ ] Automatic recording setup provides a normal-user flow based on current
      screen capture.
- [ ] The standard flow does not require typing raw template paths or raw test
      frame text.
- [ ] Plugin can capture the chosen OBS visual target and send it to Worker.
- [ ] Worker stores captured start/end templates only under `user_data/`.
- [ ] Worker image matching replaces or extends the byte-marker MVP for
      practical captured template use.
- [ ] Threshold and confirmation count have user-facing labels and documented
      behavior.
- [ ] Automatic detection receives bounded periodic frame input only when
      enabled and Worker is healthy.
- [ ] Manual Start/Stop remains usable regardless of automatic detection feed
      state.
- [ ] Current-screen detection test does not start or stop recording.
- [ ] Detection diagnostics distinguish missing template, capture failure, no
      match, strict threshold, and ambiguous start/end match.

## Documentation And Release Acceptance

- [ ] `docs/architecture/` documents final Dock UI structure, YouTube readiness,
      and guided automatic recording responsibilities.
- [ ] User-facing docs explain setup and troubleshooting without requiring API
      knowledge.
- [ ] Roadmap, traceability, readiness, release summary, and release history are

- [ ] Markdown link validation passes.

- [ ] Worker tests pass for changed Worker behavior.
- [ ] Plugin Release build passes.
- [ ] Real OBS smoke validation records Plugin load, Worker health, Dock layout,

- [ ] `v1.1.4` release tag, GitHub Release, checksums, and release notes are
