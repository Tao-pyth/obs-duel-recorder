# v1.1 Match Metadata - Acceptance Checklist

This document defines the acceptance criteria for **v1.1 - Match Metadata** as described in:

- `docs/roadmap.md`
- `docs/requirements/requirements.md`
- #320

## Scope

v1.1 creates match metadata management:

- opponent deck input
- Match Memo support
- title template engine
- Description metadata output
- Notes section generation
- metadata DB persistence
- upload metadata support

## Non-goals

- Full statistics UI.
- Export/import behavior.
- OCR-derived metadata.
- Advanced tagging.

---

## Acceptance Checklist

### A. Metadata Contract And Persistence

- [x] Canonical metadata fields and length rules are documented.
- [x] SQLite migration adds match metadata fields without replacing existing records.
- [x] Existing v1.0 upload queue records remain valid after migration.
- [x] Insert, update, read, and search behavior is covered by tests.
- [x] Metadata persists across Worker restart.

### B. Metadata Input And Editing

- [x] Worker API can create and edit opponent deck.
- [x] Worker API can create and edit Match Memo.
- [x] Result/timestamp/local linkage fields can be edited through the same metadata boundary.
- [x] Validation failures are actionable and non-destructive.
- [x] Post-upload edit behavior is documented.

### C. Upload Metadata Generation

- [x] Supported title template variables are documented.
- [x] Missing values and unknown template variables have deterministic fallback behavior.
- [x] Title and description length constraints are handled.
- [x] Description and Notes generation are deterministic.
- [x] Upload processing returns generated metadata when a queue item is linked to a match.

### D. Verification

- [x] Metadata persistence tests pass.
- [x] Title template tests pass.
- [x] Description and notes generation tests pass.
- [x] Migration from v1.0 data is covered.
- [x] Documentation validation passes.
