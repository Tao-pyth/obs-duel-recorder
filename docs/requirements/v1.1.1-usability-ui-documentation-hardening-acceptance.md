# v1.1.1 Usability UI And Documentation Hardening Acceptance

This checklist defines the active usability-based `v1.1.1` target coordinated by #440.

`v1.1.1` is not complete until every required child issue below is closed or explicitly deferred by maintainer approval. The scope follows the completed #415 / `v1.1.0` hardening issue set and focuses on UI, documentation, automatic recording setup flow, validation, and release completion.

- [ ] #441 keeps Roadmap, README, traceability, acceptance, readiness, release policy, and release-history records synchronized with #440.

## F. Validation And Release Completion

- [ ] #450 records comprehensive validation results for the UI and documentation changes.
- [ ] #451 builds or prepares the release package, validates the package, records SHA256 checksums, records the final tag/publication decision, and updates durable release records.
- [ ] #440 closes only after #441 through #451 are complete or explicitly deferred with maintainer approval.

## Non-Goals

- Moving, deleting, or overwriting legacy tags.
- Distributing Yu-Gi-Oh! Master Duel assets, local templates, screenshots, videos, OAuth files, or secrets.
- Treating a local CMake or OBS availability blocker as successful Plugin release proof.
- Publishing a release package without package validation, checksum records, and a documented publication decision.
