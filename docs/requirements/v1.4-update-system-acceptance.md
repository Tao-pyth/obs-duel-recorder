# v1.4 Update System - Acceptance Checklist

This document defines the acceptance criteria for **v1.4 - Update System** as described in:
- `docs/roadmap.md`
- #323

## Scope

v1.4 creates safe runtime update support:
- update entrypoint
- version checking
- DB backup
- migration execution
- rollback-safe update flow
- runtime preservation

## Acceptance

- [x] `update.bat` is the canonical Windows update entrypoint.
- [x] Update validation detects current and target versions.
- [x] API compatibility checks run before update mutation.
- [x] Unsupported downgrade paths fail with actionable diagnostics.
- [x] DB backup is created before migration execution when a DB exists.
- [x] Backup location and naming are documented.
- [x] Migration success and failure paths are covered by tests.
- [x] Normal update does not delete or reset runtime data.
- [x] Runtime root override behavior is supported by the update CLI.
- [x] Partial update state is detectable.
- [x] Rollback boundary and DB restore guidance are documented.
- [x] User docs cover update, backup, rollback, and runtime preservation.
- [x] Diagnostics do not expose OAuth secrets or local media contents.
- [x] Existing `/health`, `/version`, `/setup/*`, `/exports`, and earlier Worker APIs remain compatible under the v1.4 API gate.

- Update script: `update.bat`
