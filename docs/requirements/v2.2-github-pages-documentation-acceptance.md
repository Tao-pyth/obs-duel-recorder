# v2.2 GitHub Pages Documentation - Acceptance Checklist

This document defines the acceptance criteria for **v2.2 - GitHub Pages Documentation** as described in:
- `docs/roadmap.md`
- #326

## Scope

v2.2 creates user-facing documentation publication support:
- GitHub Pages support
- docs publication flow
- user setup documentation
- troubleshooting documentation
- FAQ system

## Acceptance

- [x] GitHub Pages publication flow is documented and reproducible.
- [x] Documentation source paths and generated/publication paths are clearly separated.
- [x] User setup documentation covers install, first setup, OBS setup, YouTube setup, update, and runtime preservation.
- [x] Troubleshooting documentation covers common Worker, Plugin, upload, update, queue, and recognition failures.
- [x] FAQ entries are converted from TODO placeholders into concrete user-facing answers.
- [x] Published docs do not include secrets, logs, databases, screenshots, videos, OAuth files, or game assets.
- [x] Markdown link validation runs before publication.
- [x] Japanese user docs remain traceable to canonical English/user docs without contradiction.
- [x] Release packaging docs and GitHub Pages docs do not conflict about what is published versus what is shipped.
- [x] Existing release and traceability docs link the published documentation entry point.

## Evidence

- Markdown validation: `powershell -NoLogo -NoProfile -ExecutionPolicy Bypass -File docs\tools\validate_markdown_links.ps1`
- Japanese coverage: `python scripts\validate_jp_user_docs_coverage.py --root .`
- Publication workflow dry run or artifact evidence: `python scripts\build_docs_site.py --root . --output build\docs-site`
- User docs review notes: PR #381 completed the v2.2 Japanese user docs and Pages publication review.
