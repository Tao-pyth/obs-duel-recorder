# v0.9 Screenshot System - Acceptance Checklist

This document defines the acceptance criteria for **v0.9 - Screenshot System** as described in:

- `docs/roadmap.md`
- `docs/requirements/requirements.md`
- #250

## Scope

v0.9 creates the first Worker-owned screenshot archive boundary:

- screenshot capture
- deterministic screenshot naming rules
- screenshot DB linkage
- upload-related screenshot cleanup
- screenshot preview support

## Non-goals

- OCR-driven screenshot classification.
- Upload execution or YouTube API integration.
- Shipping game screenshots or assets.
- Full user-facing screenshot gallery UI.

---

## Acceptance Checklist

### A. Screenshot Capture And Naming

- [x] Worker exposes a screenshot capture endpoint.
- [x] Screenshot bytes are stored under `user_data/data/screenshots/`.
- [x] Generated screenshot paths are deterministic and path-safe.
- [x] Existing screenshot paths are not overwritten.
- [x] Invalid or empty capture payloads return stable error codes.

### B. DB Linkage

- [x] SQLite has a `screenshots` table managed by migration.
- [x] Screenshot records can link to `matches.id`.
- [x] Screenshot records can link to `upload_queue.id`.
- [x] Invalid DB linkage is rejected without leaving orphan screenshot files.
- [x] Screenshots can be listed by match or queue item.

### C. Upload Cleanup

- [x] Cleanup is available through a Worker API endpoint.
- [x] Cleanup deletes screenshots only after cleanup-safe terminal queue states.
- [x] Upload failures, quota waits, and manual-review states preserve screenshot evidence.
- [x] Cleanup updates DB status instead of deleting metadata rows.

### D. Preview Support

- [x] Worker exposes screenshot record and preview endpoints.
- [x] Preview responses include content type and base64 content when available.
- [x] Missing files are diagnosable and mark records `missing`.

### E. Worker API Boundary

- [x] Existing `/health`, `/version`, `/overlay/state`, `/recording/*`, `/queue/*`, and `/detection/*` compatibility is preserved.
- [x] Worker API tests cover capture, DB linkage, preview, cleanup, and invalid payload behavior.
- [x] Runtime screenshots, DBs, logs, videos, and generated media are not committed.
