# v0.1 Repository Foundation Acceptance Checklist

This checklist defines the expected completion state for v0.1 Repository Foundation.

Source documents:
- `docs/roadmap.md`
- `AGENTS.md`
- `docs/requirements/requirements.md`

`docs/roadmap.md` remains the canonical roadmap and should not be changed while completing this checklist.

## Scope

v0.1 establishes repository structure and documentation structure only.

In scope:
- repository scaffold
- documentation index and cross-links
- application directory placeholders
- runtime directory placeholders
- repository metadata templates
- `.gitignore` runtime-safety rules

Out of scope:
- Worker implementation
- OBS Plugin implementation
- SQLite schema implementation
- YouTube upload implementation
- OCR or template matching implementation
- generated runtime data
- game assets or screenshots

## Acceptance Criteria

- [ ] `app/` exists and documents the application-code boundary.
- [ ] `app/plugin/` exists and documents OBS Plugin responsibilities.
- [ ] `app/worker/` exists and documents Python Worker responsibilities.
- [ ] `app/ui/` exists and documents UI ownership boundaries.
- [ ] `user_data/` exists and documents runtime-data preservation rules.
- [ ] Runtime directories contain only commit-safe placeholders or documentation.
- [ ] `.gitignore` excludes runtime data, databases, logs, secrets, tokens, generated videos, screenshots, and exports.
- [ ] Placeholder files remain trackable where needed to preserve empty directories.
- [ ] `scripts/` exists and documents script ownership boundaries.
- [ ] `.github/` contains issue and pull request templates for docs-first development.
- [ ] `docs/README.md` links to roadmap, requirements, architecture docs, and user docs.
- [ ] README links to the documentation index and canonical documents.
- [ ] `docs/roadmap.md` is not modified as part of v0.1 completion work.
- [ ] No implementation code is added for Worker, Plugin, SQLite, upload, OCR, template matching, or runtime processing.
- [ ] No Yu-Gi-Oh! Master Duel assets, game screenshots, template images, credentials, tokens, logs, databases, or generated media are committed.

## Responsibility Boundaries

The OBS Plugin area is responsible for OBS integration, Dock UI integration, overlay control, and Worker lifecycle management.

The Python Worker area is responsible for queue processing, SQLite, image analysis, OCR, upload processing, exports, and recovery behavior.

Heavy processing must not be placed in the OBS Plugin area.

## Runtime Data Boundary

Application files live under `app/`.

User runtime data lives under `user_data/` and must persist across updates.

Runtime data must not be mixed into application directories.
