# v1.1 First Trial Usability Hardening Acceptance

This checklist defines the active usability-based `v1.1.0` target coordinated by #415.

`v1.1.0` is not complete until every required child issue below is closed or explicitly deferred by maintainer approval. The scope is based on the first real OBS trial after `v1.0.1`.

## A. Installation Guidance And Safety

- [x] #416 documents the correct OBS Plugin layout with `obs-plugins/64bit/` and `obs-plugins/worker/` as sibling directories.
- [x] #417 provides a user-facing install layout verification command.
- [x] Wrong `obs-plugins/64bit/worker/` placement is detected or documented with an actionable fix.

## B. Worker Launch Failure Diagnostics

- [x] #418 reports exact Worker discovery failures from the Plugin.
- [x] #419 shows copyable Worker launch diagnostics in the Dock.
- [x] #420 records safe Worker launch command and exit evidence in logs.
- [x] Diagnostics remain free of OAuth tokens, client secrets, bearer strings, and unrelated environment dumps.

## C. Recording Completion Visibility

- [x] #421 displays the last manual recording result in the Dock.
- [x] #422 displays the recording output path or best available output evidence.
- [x] Start/Stop remains disabled unless Worker state is `running`.

## D. First-Run Setup

- [x] #423 adds a first-run setup validation UI to the Dock.
- [x] #424 provides stable Worker/API validation output for first-run checks.
- [x] A first-time user can reach Worker `running` without editing JSON manually.

## E. Recording-To-Queue Handoff

- [x] #425 creates or links a durable match record after manual recording completion.
- [x] #426 creates or documents the upload queue item after completed recording.
- [x] #427 shows basic queue state in the Dock.
- [x] Handoff behavior is idempotent and does not create duplicate records.

## F. Practical Automatic Recording

- [x] #428 provides template configuration editing or assisted registration.
- [ ] #429 provides a template matching test workflow before automatic recording is enabled.
- [ ] #430 connects practical detection flow to recording Start/Stop.
- [ ] Documentation distinguishes template detection from OCR/image-recognition metadata candidates.

## G. Production YouTube Upload

- [ ] #431 implements an optional production GoogleUploader for YouTube `videos.insert`.
- [ ] #432 adds YouTube OAuth setup and token refresh workflow.
- [ ] #433 adds upload manual-review and retry controls to the UI.
- [ ] Upload tests can still run without Google credentials or network access.

## H. Metadata Editing UI

- [ ] #434 adds match metadata editing UI for completed recordings.
- [ ] #435 adds title and description preview for upload metadata.
- [ ] Recognition candidates remain suggestions and do not overwrite metadata automatically.

## I. Distribution Improvements

- [ ] #436 adds an install/update assistant for packaged ZIP users.
- [ ] #437 records the installer/MSI decision before release readiness closes.
- [ ] ZIP users have a reliable supported install/update path even if MSI is deferred.

## J. Documentation And Release Records

- [ ] #438 keeps Roadmap, README, traceability, acceptance, readiness, release policy, and release history records synchronized with #415.
- [ ] Release policy records how to handle the legacy `v1.1.0` tag conflict before publication.
- [ ] Release history records the v1.0.1 next-version handoff to #415.
- [ ] Documentation validation passes.

## Non-Goals

- Moving, deleting, or overwriting legacy tags.
- Distributing Yu-Gi-Oh! Master Duel assets, local templates, screenshots, videos, OAuth files, or secrets.
- Treating mock upload as proof of production YouTube upload.
