# v0.7 Queue Recovery System - Acceptance Checklist

This document defines the acceptance criteria for **v0.7 - Queue Recovery System** as described in:

- `docs/roadmap.md`
- `docs/requirements/requirements.md`
- #248

## Scope

v0.7 creates the first recovery-safe upload queue runtime:

- queue resume handling
- interrupted upload reconciliation
- upload retry and network retry handling
- `quota_waiting` state
- `need_manual_review` state
- manual adjudication contract for `need_manual_review`
- startup recovery processing

## Non-goals

- YouTube OAuth and actual `videos.insert` upload execution.
- Template matching and automatic duel detection.
- Queue UI design beyond API-visible evidence.
- Persisting runtime videos, screenshots, logs, databases, or generated media in the repository.

---

## Acceptance Checklist

### A. Queue Persistence And Recovery

- [x] Queue items persist in SQLite under `user_data/`.
- [x] Startup recovery is idempotent across repeated Worker restarts.
- [x] `ready_upload`, `upload_failed`, and `quota_waiting` remain resumable after restart.
- [x] Queue transitions are encoded in focused Worker tests.

### B. Interrupted Upload Reconciliation

- [x] Interrupted `uploading` items are detected on startup.
- [x] Items with a persisted YouTube success marker recover to `uploaded`.
- [x] Items with a missing absolute local video path recover to `discarded`.
- [x] Ambiguous interrupted uploads recover to `need_manual_review` to avoid duplicate uploads.

### C. Retry And Quota Handling

- [x] Upload/network failures increment persisted retry count.
- [x] Retry state survives restart through SQLite.
- [x] Retry limit exhaustion moves the item to `need_manual_review`.
- [x] Quota failures move to `quota_waiting` with persisted `next_attempt_at`.
- [x] Operator retry can move retryable states back to `ready_upload`.

### D. Manual Review Contract

- [x] Queue items can enter and remain in `need_manual_review` safely.
- [x] Manual review evidence is persisted as structured JSON.
- [x] Allowed operator actions are documented: retry, discard, mark uploaded.
- [x] #237 is satisfied by `docs/architecture/queue.md`.

### E. Worker API Boundary

- [x] Worker exposes queue recovery and item command endpoints through localhost API routes.
- [x] API payloads are validated with stable error codes.
- [x] Invalid transitions return deterministic diagnostics and do not corrupt state.
- [x] Existing `/health`, `/version`, `/overlay/state`, and `/recording/*` compatibility is preserved.
- [x] Worker tests cover queue defaults, retry, quota waiting, manual review, invalid transitions, and startup recovery.
