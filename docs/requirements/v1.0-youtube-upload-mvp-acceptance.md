# v1.0 YouTube Upload MVP - Acceptance Checklist

This document defines the acceptance criteria for **v1.0 - YouTube Upload MVP** as described in:

- `docs/roadmap.md`
- `docs/requirements/requirements.md`
- #318

## Scope

v1.0 creates the first Worker-owned upload execution boundary:

- YouTube OAuth and secret-handling contract
- upload-only OAuth scope
- upload queue execution through `videos.insert` semantics
- upload success detection
- `youtube_video_id` and `youtube_url` persistence
- upload state management
- upload failure handling
- restart-safe upload recovery behavior

## Non-goals

- Full OAuth/setup wizard UX.
- Real-account smoke as a mandatory CI requirement.
- v1.1 metadata templates, description generation, or title templating.
- Public-by-default uploads.

---

## Acceptance Checklist

### A. OAuth And Secret Safety

- [x] The OAuth scope is limited to `https://www.googleapis.com/auth/youtube.upload`.
- [x] Client secrets and tokens live under `user_data/config/secrets/`.
- [x] Client secrets and tokens remain excluded from git.
- [x] Upload status reports whether secrets are configured without returning secret values.
- [x] Diagnostics redact tokens, authorization codes, client secrets, and bearer strings.
- [x] Default upload privacy is `private`; `unlisted` is allowed only by explicit setting.
- [x] No new Google dependency is added for v1.0; the Worker exposes a deterministic local upload boundary that can be replaced by a real client later.

### B. Upload Worker Flow

- [x] Worker selects `ready_upload` items deterministically by queue id.
- [x] Worker moves successful uploads through `ready_upload` -> `uploading` -> `uploaded`.
- [x] Successful upload persists `youtube_video_id`.
- [x] Successful upload persists or derives `youtube_url`.
- [x] Missing local video files are discarded with evidence.
- [x] Network failures move to retryable `upload_failed`.
- [x] Quota failures move to `quota_waiting`.
- [x] Ambiguous upload outcomes move to `need_manual_review`.
- [x] Startup recovery does not blindly retry interrupted `uploading` items.

### C. Status And Manual Review Surface

- [x] Worker exposes upload status through `GET /upload/status`.
- [x] Worker exposes upload execution through `POST /upload/process-next`.
- [x] Queue states distinguish `uploading`, `uploaded`, `upload_failed`, `quota_waiting`, `need_manual_review`, and `discarded`.
- [x] Manual review actions are available through the queue command API: `retry`, `discard`, and `mark_uploaded`.
- [x] `mark_uploaded` requires a YouTube video id and derives the URL when omitted.
- [x] `discard` records a reason and optional evidence.
- [x] Retry/manual decisions can preserve audit evidence.

### D. Verification

- [x] Worker tests cover successful upload, network failure, quota exceeded, missing file, ambiguous failure, secret redaction, and no-op behavior.
- [x] Existing queue startup recovery tests cover interrupted `uploading` reconciliation.
- [x] Documentation validation passes.
- [x] Japanese user docs coverage validation passes.
- [x] Plugin build remains compatible with the updated Worker API version gate.
