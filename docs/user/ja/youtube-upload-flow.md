# YouTubeアップロード操作フロー

ステータス注記: このページはv1.1.7のDockアップロード体験を説明します。実際のアップロードには、Workerの起動、YouTube OAuth設定、存在するローカル動画ファイル、Googleアップロード依存ライブラリを含む配布版が必要です。

## 通常フロー

1. 録画タブで対戦を録画します。
2. 対象動画のサムネイルと代表フレームを確認します。
3. Deck、Opponent deck、Rank、DP、結果、メモを入力または確認します。
4. メタデータを保存します。
5. アップロードタブを開きます。
6. アップロード対象、タイトル、説明文、タグ、実行可否、公開範囲を確認します。
7. 公開範囲を`private`または`unlisted`から選び、保存します。
8. `Upload to YouTube`を押します。
9. 開始前の確認で、キュー項目、動画パス、タイトル、公開範囲を確認します。
10. 成功後に表示されるYouTube URLから動画を開きます。

初心者向けにいうと、PluginはOBS Dockの画面操作とローカルWorker API呼び出しだけを担当します。キュー、メタデータ生成、OAuthファイル、YouTubeへのアップロード実行はWorkerの担当です。Workerが起動していない場合、Dockからアップロードはできません。

## アップロード対象の確認

Dockは次の状態ではアップロードを止めます。

- キュー状態が`ready_upload`または`upload_failed`ではない
- ローカル動画ファイルが見つからない
- タイトル、説明文、タグが空
- キュー項目にYouTube動画IDが既に保存されている
- キュー項目がアップロード済みまたは破棄済み

アップロード不可の場合は、実行可否の表示と詳細を確認してから対応します。手動確認待ちの項目は、YouTube側に途中作成された動画や重複動画がないか確認するまで再試行しないでください。

## 復旧操作

`Retry Upload`はネットワーク障害など、繰り返しても安全な失敗に使います。`Discard Upload`はローカルファイルがない場合や、その項目を今後アップロードしない場合に使います。`Mark Uploaded`はYouTube上に動画が存在することを確認し、YouTube動画IDを入力できる場合だけ使います。

クォータ失敗は`quota_waiting`になります。クォータリセットを待ってから再試行します。認証失敗は手動確認待ちになります。再試行前に再認証またはトークン更新を行います。

## 安全な報告

アップロード問題を報告する場合は、キュー項目ID、キュー状態、readiness state、next action、秘匿情報を除いたWorkerログ、ローカル動画が存在するかを共有してください。OAuthファイル、トークン、`code=...`を含む認証URL、ローカル動画、スクリーンショット、テンプレート画像、ゲーム資産は添付しないでください。
